# User requirements acceptance audit

Read-only audit of all 34 numbered sections in [`requirements.md`](requirements.md), against source at HEAD `2facad5`, UI, targeted tests, current CI evidence, and the dated records in [`validation.md`](validation.md). The working tree was clean at audit start. No code, UI, database, or running process was changed; no suite was run in this audit.

**Status meanings:** PROVEN means a source path plus a relevant test or recorded probe supports the stated behavior; it does not imply full release acceptance. INCOMPLETE means a material requested capability or evidence is missing. UNAVAILABLE_BY_PROTOCOL means the current Codex telemetry surface does not provide the requested exact measurement. NEEDS_LIVE_VALIDATION means implementation exists but requires installed Windows runtime/interaction evidence.

## Priority gaps found

1. Add a visible UI control for the Doctor-gated recovery acknowledgement and perform a Root-controlled production-command proof test; keep auto-resume blocked until review completes.
2. Label daily aggregate points and partial-day coverage in the history UI so they cannot be mistaken for individual observations.
3. Add per-event notification controls and implement/test the missing requested notification classes.
4. Decide whether to collect missing thread timing/current-turn/model-context fields; otherwise keep them explicitly unavailable.
5. Reconcile README/PROGRESS/ROADMAP/security-gate status with current `validation.md` before release.
6. Rebuild through the source-path remapping wrapper and rerun the strict package check: require `Read-SystemProxy.ps1`, no private absolute paths in ASCII or UTF-16LE, and the same normalized single-marker executable equality. Then finish Root-owned Windows restart validation.

## Live evidence boundary

The live Normal and Goal smoke evidence is two real `gpt-6-luna/low` calls, one turn each, using owned `thread_source=agent` fixtures excluded from the Core catalog/ledger. The Goal trigger was manually set to `usageLimited` and is therefore simulated. Both completed fixtures remain unarchived because the current AppServer `thread/archive` returned `-32600`; no Core/database manipulation or owner shutdown was used. This is separate from—and does not satisfy—the natural quota-cycle requirement.

Maintenance/pricing/statistics targeted evidence: `test/acceptance-maintenance.test.mjs` **6/6**, `test/acceptance-statistics.test.mjs` **2/2**, and `test/observability.test.mjs` **23/23**, combined **31/31**. It uses synthetic v1/v2 and corrupt temporary databases, a synthetic owner directory/current-PID lease, a temp Worker/router SQLite file, and no official pricing network request or live account database. Core settings/policy/manual-resume gates reject recovery-review state before quota reads or turn dispatch; statistics acceptance keeps request/turn/context/tier values and performance quality within their proper ledgers.
